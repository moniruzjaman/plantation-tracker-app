## 1. Critical — Action Required

### 1.1 Android build is broken: missing `capacitor-cordova-android-plugins` directory

`android/settings.gradle` line 2-3 references:
```groovy
include ':capacitor-cordova-android-plugins'
project(':capacitor-cordova-android-plugins').projectDir = new File('./capacitor-cordova-android-plugins/')
```

The directory `android/capacitor-cordova-android-plugins/` does **not exist**.
This causes `gradle sync` and any Android build to fail with:
```
Project ':capacitor-cordova-android-plugins' not found in root project.
```

**Fix:** Run `npx cap sync android` from the repo root. This regenerates the
Cordova plugins stub directory. If that doesn't create it (Capacitor 8 may
have dropped it), remove the two `settings.gradle` lines and the
corresponding `build.gradle` entries (`dirs ... 'capacitor-cordova-android-plugins/src/main/libs'`,
`implementation project(':capacitor-cordova-android-plugins')`,
`apply from: 'capacitor.build.gradle'`). In Capacitor 8.x the Cordova
bridge is built into the core `capacitor-android` module — the separate
`capacitor-cordova-android-plugins` project was removed upstream.

### 1.2 `api/audit/[...slug].ts` — `totalSeedlings` used outside its scope (TS error)

Lines 58-81 of `api/audit/[...slug].ts`:
```ts
// Inside the for loop:
totalSeedlings += seedCount;  // line 58 — this is a loop-level var

// After the loop:
res.status(200).json({
  report: {
    totalSeedlings,          // line 81 — shorthand for undeclared variable
  },
});
```

`totalSeedlings` is never declared with `let`/`const` outside the loop, so
TypeScript reports `TS2304: Cannot find name 'totalSeedlings'` and
`TS18004: No value exists in scope for the shorthand property`. The code
will crash at runtime when `/api/audit/carbon-stock` is called.

**Fix:** Add `let totalSeedlings = 0;` before the `for` loop (mirrors what
the original `server.ts` carbon-stock handler does).

### 1.3 `api/auth.ts` — wrong import path (`../_lib/` should be `./_lib/`)

`api/auth.ts` sits at the `api/` root (same level as `_lib/`), but it imports
with `../_lib/` (going up one level to the repo root, then into `_lib/`).
This resolves to nothing — TypeScript can't find the module, and Vercel's
build will fail for this route.

**Fix:** Change all three imports:
```ts
// BEFORE (wrong):
import { prisma } from '../_lib/prisma';
import { getAllowList, findInAllowList } from '../_lib/auth';
import { setCorsHeaders, parseBody } from '../_lib/helpers';

// AFTER (correct):
import { prisma } from './_lib/prisma';
import { getAllowList, findInAllowList } from './_lib/auth';
import { setCorsHeaders, parseBody } from './_lib/helpers';
```

### 1.4 `npm run lint:api` fails (4 TypeScript errors)

```

api/audit/[...slug].ts(81,11): error TS18004: No value exists in scope...
```

## 2. Capacitor Drift

### 2.1 `@capacitor/assets@3.0.5` — stale, wrong major version

`package.json` declares `@capacitor/assets: ^3.0.5` (Capacitor **3** era),
but all other Capacitor packages are `^8.3.0` / `8.4.2`. The assets
package is a dev-time tool for generating splash screens and icons — it
has **zero peer dependencies** (empty `peerDeps: {}`), so it installs
silently without version conflict, but it can't produce Capacitor 8–compatible
assets (the API changed in Capacitor 5/6).

**Impact:** `generate-icons.js` (65 lines, **unreferenced** by any script)
uses this package. The `icons/` directory already has pre-generated webp
files. If you ever re-run `generate-icons.js`, it will produce Capacitor 3–
format output which may not match what Capacitor 8 expects.

**Fix:** Upgrade to `@capacitor/assets@^8.0.0` or remove it if the icons
are regenerated by `download-and-process-logo.js` instead.

### 2.2 `capacitor.config.ts` — generic `appId` and `appName`

```ts
appId: 'com.nursery.app',
appName: 'plantation-tracker',
```

- `com.nursery.app` is the reverse-domain identifier used for the Android
  package and the `android:namespace` in `build.gradle`. If this is
  intentional (the app was originally called "Nursery App"), it's fine —
  but it should match the Google Play Store listing. If the app is now
  called "KrishiAI" or "বৃক্ষরোপণ ট্র্যাকার", consider changing it to
  `com.krishiai.app` or `com.dae.plantationtracker`. **Once published to
  Play Store, the appId cannot be changed without a new listing.**
- `appName` is used for the Android launcher label (`@string/app_name`).
  Currently it's the English slug `plantation-tracker` — the Bengali name
  `বৃক্ষরোপণ ট্র্যাকার` is only in the PWA manifest's `short_name`.

### 2.3 Android SDK versions — modern, no issues

`android/variables.gradle`:
```groovy
compileSdkVersion = 36
targetSdkVersion = 36
minSdkVersion = 24
```

These are current. `compileSdk 36` (Android 16) is the latest as of July 2026.
`minSdk 24` (Android 7.0 Nougat) is appropriate for a field-data app
targeting government officers on budget devices.

### 2.4 Capacitor 8.4.2 — all three core packages aligned

```
@capacitor/core:    8.4.2  ✅
@capacitor/cli:     8.4.2  ✅
@capacitor/android: 8.4.2  ✅
@capacitor/geolocation: 8.2.0  (minor lag, no breaking changes)
```

No version mismatch between core/cli/android. Geolocation is one minor
version behind — safe to upgrade to `^8.3.0` but not urgent.

## 7. Build & Config Issues

### 7.1 GitHub Actions CI — branch filter is stale

`.github/workflows/build.yml` triggers on:
```yaml
on:
  push:
    branches: [ main, master, better-gilmoreosaurus ]
```

The branch `better-gilmoreosaurus` is likely an old Vercel deployment branch
that no longer exists. Adding `neon-reconnect` to the trigger list (or just
using `main` only) would ensure CI runs for the modernization branch.

### 7.2 CI runs `npm run build` which includes `build:server` (esbuild)

The CI step `npm run build` runs both `build:web` (Vite) and
`build:server` (esbuild bundles `server.ts`). Since `server.ts` is now
local-dev only and the Android build doesn't need the bundled server,
the CI could skip `build:server` and save ~10 seconds. Alternatively,
change `build` to just `build:web` since Vercel handles the serverless
functions independently.

### 7.3 Duplicate PWA manifests

Two PWA manifests exist:
1. `public/manifest.webmanifest` — static file with icons, theme, etc.
2. `vite.config.ts` → `VitePWA({ manifest: {...} })` — inline manifest config.

Both define the same app name, icons, and colors. If they diverge, the
behavior depends on which one the service worker picks up. VitePWA's
inline config should take precedence, making `public/manifest.webmanifest`
a fallback. Consider removing the static file to avoid confusion.

### 7.4 `prisma` deprecation warning

```
warn The configuration property `package.json#prisma` is deprecated and
will be removed in Prisma 7.
```

The `prisma` key in `package.json`:
```json
"prisma": { "schema": "prisma/schema.prisma" }
```

Migrate to a `prisma.config.ts` file at the repo root before upgrading
to Prisma 7.
